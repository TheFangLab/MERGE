## 1. Quick answer: what stops commercial use

Most of what MERGE calls is permissively licensed. Four components are not, and
they are the only reason MERGE cannot simply be declared commercial-friendly
end to end:

| Component | Restriction | Avoidable? |
|---|---|---|
| **AlphaGenome** | Non-commercial only; outputs must not train other ML models | No — see §4 |
| **Nucleotide Transformer** (v1 and v2) | CC BY-NC-SA 4.0 — non-commercial *and* share-alike | Yes — `--no-nt --no-nt-v2` |
| **dbNSFP** (academic branch) | CC BY-NC-ND 4.0; commercial use needs a paid licence | Partly — only the coding panel reads it; see §3 |
| **ANNOVAR** | Personal / academic / non-profit only; no redistribution | Yes — pass `--ensemble-type` explicitly |

A model you skip has its feature median-imputed by the ensemble pipeline rather
than causing an error, so dropping the restricted ones leaves a working — if
less accurate — configuration.

## 3. Precomputed variant scores looked up at prediction time

> **How MERGE reads these two.** Both `AlphaMissense_score` and `ESM1b_score`
> reach MERGE through **dbNSFP**, not from the originators directly. The
> licences below are the originators' own and are genuinely permissive —
> AlphaMissense predictions are CC BY 4.0 and the ESM-1b variant scores are MIT,
> so **neither model restricts commercial use** — but the copy MERGE reads is
> dbNSFP's, so **dbNSFP's CC BY-NC-ND terms are the ones that bind you in
> practice**. The constraint is the aggregator, not either predictor.
>
> There are three ways out, and they are not equivalent: buy a dbNSFP commercial
> licence (both columns are in its commercial branch, and the values are the ones
> the model was trained on); re-source from the originators (permissive, but the
> values differ — measured below, and it changes what the model is fed); or run
> `--no-alphamissense --no-esm1b` and accept a weaker coding panel. See the
> dbNSFP entry below.

### dbNSFP ⚠️ non-commercial

MERGE reads two columns out of dbNSFP — `AlphaMissense_score` and `ESM1b_score`
— plus the gene name and Ensembl transcript ID. Nothing else.

**Where this matters:** those two scores appear in the **coding** feature panel
only. The splicing, non-coding and non-SNV panels never touch dbNSFP.

* **Academic branch licence**: **CC BY-NC-ND 4.0**. Three separate constraints,
  all of which are yours to honour, not ours to waive:
  * **BY** — attribute dbNSFP (cite Liu et al.) in anything you publish.
  * **NC** — no commercial use.
  * **ND** — no derivatives. Do not redistribute modified dbNSFP content.
* **Commercial use** requires a paid licence from Genos Bioinformatics LLC.
  Published tiers: internal research USD 5,000/year; product development and
  internal research USD 10,000/year. Contact license@dbnsfp.org.
* **The commercial branch does carry both columns MERGE reads.** dbNSFP's
  commercial ("c") branch drops the components whose authors require a separate
  commercial licence — CADD, VEST, M-CAP, MutScore, PolyPhen-2, PrimateAI and
  RGC Million Exome — and **ESM1b and AlphaMissense are not among them**
  (verified against <https://www.dbnsfp.org/license>, dbNSFP 5.4, August 2026).
  So a dbNSFP commercial licence is a complete route to a commercially usable
  coding panel with the values the model was trained on. It is the only route
  that does not also change what the model is fed — see below.
* **Legacy versions**: dbNSFP states that a commercial licence is not required
  for v4.x and earlier, as a courtesy. That does not help here — v4.5, the first
  release with these two columns, shipped a bug that misaligned a large
  proportion of ESM1b scores, fixed only in v4.6.
* **Nested terms**: some components bundled in the academic branch (CADD, VEST,
  M-CAP, MutScore, PolyPhen-2, RGC Million Exome) carry their own separate
  commercial terms. MERGE reads none of those columns, but they are in the file
  you download, and complying with them is part of using dbNSFP.
* MERGE does not redistribute dbNSFP, or any part of it. You download it
  yourself from <https://www.dbnsfp.org/> and accept its licence there.
* Cite: Liu X, et al. dbNSFP. See <https://www.dbnsfp.org/>.

**If you need a commercially usable configuration**, run with
`--no-alphamissense --no-esm1b`: both features are median-imputed instead, and
the coding panel still scores — less accurately, since AlphaMissense is its
strongest single feature. The other three panels are unaffected either way.

**Why MERGE does not simply read these two scores from their originators.**
AlphaMissense publishes its predictions under CC BY 4.0 and the ESM-1b variant
scores are MIT, so on licence grounds alone the swap looks free. It is not, and
we measured it rather than assuming:

* DeepMind's current AlphaMissense release does not reproduce the values in
  dbNSFP 5.3a. Of 4,154 comparable coding variants only 27% match exactly
  (Pearson 0.9953). The all-isoform release matches just 3.5%, so this is a
  release-version difference, not a transcript-selection one.
* The shipped coding model embeds imputation medians and z-scoring fitted on the
  dbNSFP values, so re-sourced values would change what it is fed.
* The ESM-1b bulk release is keyed by UniProt isoform and amino-acid
  substitution, with no genomic coordinates, so it is not a lookup substitute at
  all without a full genomic-to-protein mapping step.

Changing the source would therefore mean changing what the coding model is fed,
which is a modelling decision and not a licensing one. MERGE keeps the source it
was trained on and states the terms plainly instead.

## 4. The MERGE ensemble models themselves

### The four ensembles — MIT

`MERGE_noAlphaGenome_coding.pkl`, `MERGE_noAlphaGenome_splicing.pkl`,
`MERGE_noAlphaGenome_noncoding.pkl` and `MERGE_noAlphaGenome_nonsnv.pkl` are
MERGE's own work and are **MIT**, same as the code.

They were fitted on a candidate pool with every `alphagenome_*` column removed
before any feature selection ran, so no AlphaGenome output entered their
training data and none of their panels contains an AlphaGenome feature. The
module refuses to load a bundle whose panel contains one, so this is enforced
rather than merely intended.

### The AlphaGenome percentile table — CC BY-NC 4.0 ⚠️

`alphagenome_reference_quantiles.json` supplies the AlphaGenome half of the optional
**MERGE + AlphaGenome average**, a fixed 1:1 mean of the ensemble probability and one
AlphaGenome column's percentile, offered on splicing and non-coding variants only.
It pairs every distinct AlphaGenome score observed in the MERGE benchmark with its
mid-rank percentile (`alphagenome_splicing` for splicing, `alphagenome_raw_score_max`
for non-coding).

**It is not a model trained on AlphaGenome output.** No label and no fitted parameter
is involved — it is the empirical distribution of the column.

The table is still derived from AlphaGenome output, and the AlphaGenome API is
non-commercial, so we license it **CC BY-NC 4.0** out of caution. This is a reading of
the terms without a written clarification from DeepMind; if that changes, the table
moves to MIT. (The coding and non-SNV average is not offered at all — AlphaGenome's
summaries are near chance there, AUROC 0.571 and 0.512.) Delete the file and MERGE runs
unchanged: the ensembles score as normal and `merge_alphagenome_average` comes back
`null` with a status saying the reference is unavailable.
**For commercial use, that is the supported configuration** — and the same reasoning
applies to calling AlphaGenome at all, since its API is offered for non-commercial use
only.

The **source code** of merge-cli carries no such constraint — see `LICENSE`.

### The precomputed cache

The MERGE web server ships a precomputed score cache. For variants already in
it, AlphaGenome-derived values are returned without an API key, because those
values were computed once by the MERGE team and are served as published research
data. For any variant *not* in the cache, AlphaGenome is called live and that
call requires **your own** API key. merge-cli's remote mode follows exactly the
same rule.
